3. BLOCKED / WAITING ON A PREREQUISITE
--------------------------------------------------------------------------------

B1. Firebase login page - blocked on Firebase project provisioning
    Task 7 asks for a Firebase login page. The frontend cannot do this
    alone. It needs, from outside this repo:
      - a Firebase project with email/password authentication enabled
      - real values for VITE_FIREBASE_API_KEY, VITE_FIREBASE_AUTH_DOMAIN,
        VITE_FIREBASE_PROJECT_ID, VITE_FIREBASE_APP_ID (currently blank
        in .env.example)
      - the `firebase` package added to frontend/package.json
      - a backend that verifies the ID token and returns the role claim
        (README: GET /me returns the profile and role)
    Until the Firebase project exists, login stays mocked. This is an
    infrastructure prerequisite, not a frontend decision. The role-based
    routing and guard logic it feeds is already built and tested.

B2. Task 8 real-API integration - blocked on the backend task
    Task 8's "works against the real API without code changes beyond
    VITE_USE_MOCKS" cannot be satisfied until the backend routes exist.
    frontend/src/api/client.js currently calls endpoints that do NOT
    appear in the README API table:
      client.js                          README defines
      ---------------                    ---------------------------------
      GET  /orders                       GET /orders                  match
      GET  /cases                        GET /cases                   match
      GET  /chat/{scenario}              POST /chat                   MISMATCH
      POST /chat/{scenario}              POST /chat                   MISMATCH
      POST /cases/submit                 POST /drafts/{id}/submit     MISMATCH
    Also absent from client.js but present in the README table:
      GET /me, POST /drafts/{id}/attachments, GET /drafts/{id},
      POST /cases/{id}/reply, GET /staff/cases,
      PATCH /staff/cases/{id}/status, GET /files/{attachmentId}
    Note: "{scenario}" is a mock-only construct. The README API has no
    "load a scenario" endpoint, so the scenario picker on /support is
    mock-only by nature and will need to be gated behind VITE_USE_MOCKS.

    NOTE: the backend task is referred to as "T9" because the Task 7
    brief says "T8 and T9 can start using only mocks". Confirm the
    actual task number before acting on this.

5. DEVIATIONS AND NOTES
--------------------------------------------------------------------------------

- File locations. The README's "Planned repository structure" puts all
  frontend build config under frontend/. It now does: index.html,
  vite.config.ts, package.json, tsconfig.json, vite-env.d.ts, mise.toml,
  pnpm-lock.yaml. Source lives in frontend/src/api, /components,
  /mocks, /pages as the README shows.

- vite.config.ts sets `envDir` to the repository root. Without this,
  Vite would read frontend/.env and the README's single root .env
  instruction would silently stop working.

- The Figma Make scaffold this project started from has been removed: the
  site.json import, four Figma plugins, and the 8443 default port. The
  dev server now uses 5173, matching the README's CORS_ORIGIN.

- AGENTS.md at the repo root is STALE and contradicts the code. It
  describes src/main.tsx -> src/App.tsx (actually main.jsx ->
  ./app/App), .mise.toml (actually mise.toml), and port 8443 (actually
  5173). It also states "Export components as default exports", which
  app/routes.jsx and both context files deliberately do not follow.
  Recommend rewriting or deleting it.

- README "Current project status" (line 279) says the repository
  "currently contains the product requirements and this project README"
  and that everything above is "planned ... not to be treated as
  verified". That paragraph is now out of date for the frontend and
  should be updated before submission.

- "AccessDesk PRD.md" is gitignored as local-only and is not in the
  repository. Section 2.7 was supplied separately and used to verify the
